## 4. 预存 PoW：是否真实链上模式？ → **YES**

合约（Sourcify exact_match）要点：

- `taskSeed` **只在 `startMining()` 设一次**，日切不改。
- `puzzleSeed(wallet)=keccak(publicChallenge, wallet)` → **钱包固定**；历史 eth_call 证实 refresh 前后  
  `puzzleSeed=0xdf0f5f4b…de62`、`taskSeed=0x2ce7789b…e4fe`、`currentTarget` **不变**。
- `_accept` 校验：`proofDigest(msg.sender,nonce)` vs **当前** `targetForStage(stageForClaims(successfulProofs))`；`usedProofs[proof]` **跨日永久占用**。
- 日切只影响 `miningDay` / `budgetDay` / `mintedInBudgetDay`；`DailyLimitReached` 挡提交，**不挡本地算**。
- `isLive=false` 当 `dailyRemaining < currentReward` 时，claims/target **冻结** → 死额度期间预挖的 nonce，开盘后只要还没被用、且未跨 stage 变难，**仍可直接 mineBatch**。

因此：「额度=0 时本地预挖 → 19:08:54 喷射」是合约允许的真实模式；今晚 ~58s 内 +214k claims 与此吻合。  
注意：若预挖期间别人已推高 stage（target 变严），旧 proof 可能 `InvalidSolution`；死额度阶段通常无人能上链，stage 冻结，预存最稳。
